# Decisions

- 2026-11-25: Ollama support deferred; v1 models are OpenAI, Anthropic, Google and DeepSeek for now.
- 2026-11-25: Possible duplicate knowledge points are merged by hand with `learnova kp merge <point> --into <existing>`; the review report prints the command. Not in the spec command table; review stays non-interactive.
- 2026-11-25: Mastery is always recomputed by replaying a point's attempts in time order. `kp merge` moves links in Milestone 7; Milestone 9 must extend it to move attempts and recompute mastery (with a test).
- 2026-11-25: Added `learnova kp list [--workspace]` and `learnova kp importance <point> <1-5>` (not in the spec command table) so points can be seen and importance changed before `status` exists.
- 2026-11-25: Weights use fractional days since the last quiz. A point never quizzed counts as `new_point_days` (default 7, in config.toml `[weights]`) so new points are not starved by long-unreviewed ones.
- 2026-11-25: Milestone 10 (`check-latest`) moved to version 2; version 1 ends at Milestone 9.
- 2026-11-25: Version 2 scope and order: (1) multiple choice + true/false, graded locally; (2) FastAPI on 127.0.0.1, no auth; (3) React + Vite + TypeScript frontend; (4) check-latest. Folder source and Ollama deferred. See "Version 2" in SPEC.md.
- 2026-11-25: Quiz questions are stored in `issued_questions` until answered or skipped (open ones expire after 7 days); the CLI and the API both use it. The API listens on 127.0.0.1 only and, having no auth, checks the Host header, requires JSON POST bodies and limits CORS to `[api] allowed_origins`.
- 2026-11-25: Web frontend in `frontend/` (React + Vite + TypeScript, React Router, TanStack Query, react-markdown). TypeScript is pinned to 5.x because openapi-typescript needs its compiler API (TypeScript 7 has none). `learnova serve` serves `frontend/dist` when it exists. Report lists are ordered by the date and run number in the file name, not file times.
- 2026-11-25: Version 2 ends at V2.3; `check-latest` deferred again, to a later version.
- 2026-11-25: `.learnovaignore` hides pages instead of deleting them (`notes.ignored`, migration 0008), so un-ignoring restores links to knowledge points without a new review. A page deleted in Notion while hidden is still deleted.
- 2026-11-26: Version 2.3 adds `learnova import-web` (web tutorial → Notion). First exception to "Learnova only reads Notion": it writes only under the `--into` page, never to your own note content (only the status line it created). Each article gets a user-owned notes page plus a Learnova-owned 原文 child page; only articles listed in the index are imported, in-article links are not followed. See "Version 2.3" in SPEC.md.
- 2026-11-26: Version 2.2 not started; deferred until after Version 2.3.
- 2026-11-26: import-web stores the text of each section instead of the previous Markdown (the notice compares by section), sends ETags so unchanged articles cost one cheap request, and makes one Notion page per h3 under its h2. State is in `web_imports` and `web_articles` (migration 0009).
- 2026-11-26: V2.3 redesigned: Notion gets only a one-time full import (`web import`, one plain page per article, notes written on it; no notes template, status line or 原文 sub-page). `web check` compares the site with a local Markdown cache and writes a diff report; the cache then moves on (each change reported once); new articles are only listed. Migration 0010 replaces the 0009 tables (their rows described pages deleted by hand). Supersedes the two 2026-11-26 import-web lines above.
- 2026-11-26: The `--into` page mirrors the index page (introduction, headings, descriptions, article sub-pages in place of the links) instead of one page per section. Written strictly in order; a run stops at the first error and continues from a saved step (migration 0011 replaces `section_pages` with `cursor` + `layout_hash`). Added `web forget`. Site abstraction, carousel images and auto-recreating trashed pages: not now.
- 2026-11-26: Version 2.2 redefined: issues database, block anchors, knowledge hierarchy, knowledge base as first page (Status merged in), quiz on chosen points/topic, optional Notion comments. The earlier 2.2 items (bookmarks, manual questions, guided setup) moved to Version 2.4. See "Version 2.2" and "Version 2.4" in SPEC.md.
- 2026-11-26: V2.2 M1: `review_issues` has a separate `topic` column for `missing` issues (the spec puts topic and reason in `problem`), because the fingerprint needs the topic alone. An open issue the model does not mention stays open; only an explicit `fixed` closes it.
- 2026-11-26: V2.2 M2: the quote-to-block similarity threshold is configurable (`[issues] anchor_threshold`, default 0.6). Open issues without a block (older ones, or whose paragraph was replaced) are linked again at the next review of their note.
- 2026-11-26: V2.2 M1 follow-up: a found issue counts as an existing open or dismissed one in the same note (same kind, and one quote contains the other, quotes or topics ≥ 80% alike, or same block; fuzzy rules need 3+ words), not only on an exact fingerprint. A note whose text is unchanged since its issues were last updated (`notes.issues_hash`, migration 0014) keeps them as they are; blocks are still re-linked. The spec's `kp_parents` moves to migration 0015.
- 2026-11-26: V2.2 M3: `kp organize` without `--workspace` writes its proposal to `~/.learnova/reports/` (points belong to no single workspace). Applying is all or nothing, after one confirmation. A point that becomes a topic keeps its attempts but is not quizzed, and topic mastery ignores them. Depth counts primary parents only; loops are checked over shortcuts too.
